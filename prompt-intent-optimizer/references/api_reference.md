本参考文件只记录可复用的官方指导原则，不替代源页面。使用本技能前，在以下官方地址核查最新版本；模型与 API 行为可能变化。

## 用于“语义不变改写”的规则

### 不可删的语义

始终保留：任务目标、领域上下文、范围、硬约束、禁止项、审批边界、成功标准、输出格式、必需证据/引用、停止条件、关键歧义处理、经验证有业务价值的示例。

优化时不能新增：任务、事实、工具、权限、审批要求、数据来源、输出字段、成功标准或行为限制。需要澄清时，保留原句，或提出最少的澄清问题。

### 应优先删除或合并的内容

- 同一范围和优先级的重复指令；
- 无实际约束力的重复客套、开场和结尾；
- 不必要的流程微管理；
- 不相关工具、冗长工具描述和无价值示例；
- 与当前任务无关的上下文。

每条规则只写一次。更短不等于更好；只有最终结果仍正确、完整、具有所需证据、引用、限制和格式时，才算优化成功。

## 结果优先与结构化

优先表述最终结果、可用证据、行动边界与成功标准，允许 GPT-5.6 自行选择不影响边界的执行路径。只在流程本身具有业务意义时保留明确步骤。

按需使用 Markdown 标题和列表分层；按需使用 XML 标签分隔参考文档、输入数据、示例和上下文。不要为了套模板而引入空段落或新规则。

常用段落顺序：任务 → 上下文/输入 → 约束与异常处理 → 输出格式 → 原有验证要求。对于 API 场景，稳定规则适合 `developer`/`instructions`，动态任务与数据适合 `user`/`input`；不要在未经用户要求的情况下改变原有消息优先级。

## 指令粒度、输出和示例

GPT 类模型受益于明确的任务逻辑、所需数据、处理规则和输出要求。对于严格格式任务，保留允许值、字段、顺序、数量、额外文本限制和缺失数据规则。需要时使用少量多样化的 few-shot 示例，覆盖典型、边界和异常情况；不要编造示例或标签规则。

“简短”“友好”“专业”等宽泛偏好不能凭空细化为新要求。只有用户已表达足够行为含义时，才能将其改写为可观察的写作行为。简短输出应先给结论，保留支持证据、重大限制和下一步，优先删重复和可选背景。

## 自主性、权限和停止条件

明确定义模型可直接执行、仅报告和必须确认的动作。官方紧凑策略：

- 回答、解释、审查、诊断和规划：检查相关材料并报告；除非明确要求，不实施修改。
- 修改、构建和修复：可进行范围内本地变更和非破坏性验证。
- 外部写入、破坏性操作、购买或实质扩大范围：必须先确认。

不要反复写“先问我”“不要修改”；重复会导致对安全、范围内动作的过度确认。不能把明确审批边界压缩成“谨慎处理”。

证据已足够时应交付；关键事实缺失、来源冲突或无法验证时，应说明缺口而不是猜测。停止条件和验证要求必须保留。

## GPT-5.6 特别注意

- GPT-5.6 默认更简洁。不要因为“Keep it short”看似多余就删除仍会影响完整性的要求。
- 不要默认添加“think harder”“use pro mode”或“生成多个候选答案”。
- 不要默认提高 `reasoning.effort`；应先以原设置为基线，在代表性任务中比较质量、成本和延迟。
- `max` 仅用于最困难、质量优先的任务，并应与 `xhigh` 比较。
- 不要只以 token、工具调用数、轮数或延迟降低判断改进；必须验证最终答案。

## 工具与 PTC 边界

仅当一个阶段有界、可预测，且无需模型在每个中间结果后重新作语义判断时，才适合 Programmatic Tool Calling (PTC)。只因调用多、可并行或有依赖，并不足以采用 PTC。

若原提示已经涉及 PTC，必须保留并明确：有界阶段、允许工具、文档化字段、输出 schema、所需证据、并发规则、重试上限、停止条件、避免重复和副作用的规则，以及保留给直接调用的语义判断、审批和最终验证。未知工具返回结构时，优先直接调用。

PTC 的中间 `program_output` 与最终 assistant message 都必须验证；前者正确不代表最终输出含有全部字段、引用与风险提示。

## API 与生产工作流

将稳定可复用规则放在请求前部，动态数据置后，以利于 prompt caching；缓存是否节省成本必须看真实命中与写入成本。将生产提示词作为版本化代码，通过代表性样本、边界样本和评测持续检查；改提示词、切换模型或快照时重新评估。

OpenAI 已宣布将弃用 API reusable prompt objects：从 2026-06-03 起弱化创建，`v1/prompts` 计划于 2026-11-30 关闭。新生产方案应使用代码管理的、版本化的提示词构建器与 Responses API 的 `instructions`/`input`。
